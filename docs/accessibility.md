# Accessibility

This project targets **WCAG 2.2 Level AA** across both pages — the player and
the editor — and this file is the record of what that rests on. The same claim,
written for a reader rather than for a repository, is in the application itself:
the **Accessibility** link in the footer of either page opens it.

Two things are worth saying before the table.

**The running game is not this project's content.** MGI is an interpreter for
games written by other people in the 1980s and 1990s. What appears on the game
screen is those games' artwork and text, redrawn sixty times a second, and no
text alternative can be authored for it here. Everything around the picture —
naming the screen, saying which game and which room, the engine log, every
control — is this project's, and is covered. A game's own content is not, and
saying otherwise would be a false claim rather than a conformant one.

**Automated tests catch a minority of accessibility problems.** The suite in
`tests/accessibility-*.test.ts` renders the real interface and asserts roles,
names, states, focus behaviour, keyboard movement and computed contrast. It is
the floor, not the ceiling. Nobody has yet driven this with a screen reader end
to end; where that matters it is listed under [Known limits](#known-limits).

## How it is built

The pieces are shared rather than reimplemented per surface, because the earlier
failures were all of the form "three components each did a different subset of
the same thing".

| File                           | What it owns                                                                                               |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| `src/ui/a11y.ts`               | The focus trap, the `inert` background, the polite live region, the focusable-element query, colour naming |
| `src/ui/a11y.css`              | The focus ring, the skip link, `visually-hidden`, the 24px target floor, reduced motion, forced colours    |
| `src/editor/a11yWidgets.ts`    | Roving tabindex for the palettes, strips, tabs and the AGI pixel grid                                      |
| `src/editor/canvasKeyboard.ts` | The keyboard cursor the six drawing canvases share, and the on-canvas focus indicator                      |
| `src/ui/accessibility.ts`      | The statement in the footer of both pages                                                                  |

## Known limits

These are exceptions rather than omissions, and the in-app statement names all
three.

**A running game's own pictures and words cannot be described.** Covered above.
What the application does instead: names the screen, says which game and which
room in the status line, keeps the engine log readable and focusable, and makes
every control around the picture accessible.

**The AGI cel grid uses 12-pixel cells.** One cell there is one pixel of the
artwork being edited. At 24px a cel would be four thousand pixels across and
would stop being legible as a drawing — which is 2.5.8's _essential_ exception,
and is worth naming rather than leaving as an oversight. The keyboard route is
the answer instead: the grid is one tab stop, arrow keys move within it, and
every cell is named by its row, its column and its colour.

**The AGI typing line has not been checked with a real screen reader.** Sierra's
parser games take typed commands through a visually hidden `<input>`, guarded by
`tests/agi-input-accessibility.test.ts` — but nobody has yet sat down with an
actual screen reader and typed a command into a real game. Treat it as untested
rather than as working. This is issue #130 and it stays open until someone has.

## Testing it yourself

```bash
npm test                      # includes the accessibility suite
npx vitest run tests/accessibility-focus.test.ts
npx vitest run tests/accessibility-widgets.test.ts
npx vitest run tests/accessibility-markup.test.ts
npx vitest run tests/accessibility-contrast.test.ts
npx vitest run tests/accessibility-dialogs.test.ts
```

By hand, the checks worth the most per minute:

1. Unplug the mouse. Both pages should be fully usable, including drawing a
   room, painting a costume and placing a walk box.
2. Tab into any dialog and try to leave it without Escape. You should not be
   able to.
3. Zoom to 400%. Nothing should be cut off and nothing should scroll sideways.
4. Turn on the operating system's reduced-motion and forced-colours settings.

If something here does not work for you, that is a defect. The issue tracker is
linked from the statement in the footer.
